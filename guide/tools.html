Checking, converting and comparing¶

PLATO tools works on data in PLATO’s shape. It checks a file for mistakes, converts it to another format, and shows whether a new version of a published dataset has kept what the earlier one said, and it prepares a dataset for publishing. It runs in your browser: your files are never uploaded, unless you save a workflow’s project to the World Historical Gazetteer yourself (see keeping the project in WHG). A dataset of a million places has been checked and converted there, within the storage the browser allows the page (see large datasets). It also runs from the command line, for many files at a time, with the same checks and the same reports.

To use it, open the page and drop a file on it (or choose one), then press Check, choose a format and press Convert, press Compare with the earlier version, or choose what to prepare for publishing and press Prepare. Show on the map opens Chora, which shows a dataset’s places on a map and adds the locations you draw there: see placing on the map. Not sure where to start? Methodos leads you through a whole workflow, step by step, from three questions.

Large datasets¶

These figures come from PLATO tools’ own test runs. In the browser (Chromium), a million places in the spreadsheet tables, a CSV of 296 MB, were checked, converted and saved in about 17½ minutes, using about 1.3 GB of memory and, at the peak, 3.6 GB of the browser’s storage. All of DEEP, 24.8 million triples in 2.6 GB, was read in about 10 minutes, with 756 MB of memory and 5.2 GB of storage.

In the browser, the limit is the storage the browser allows the site. Before it starts, the page estimates what a file will need and warns if that looks like too much: roughly four times the file for most formats, forty times a gzipped file, and twelve times the text of spreadsheet tables. Private windows allow very little, so use an ordinary window. How much other browsers, such as Safari, allow has not been measured.

If the page warns, use the command line. It has no storage allowance and is not held to a browser tab’s memory: the same million places converted in 6 minutes 38 seconds with 367 MB of memory. It still needs disk, about one and a half to two times the uncompressed input, so give --work-dir a folder on a disk with room if the temporary folder is small. It needs memory wherever the whole of something must be held: a workbook (.xlsx or .ods) is read whole, so save very large tables as CSV files instead; the Data Cube check holds the whole graph; and a match review holds the places of both datasets. Gzipping a file makes it smaller to keep and send, but not smaller to work on. The command line also takes many files at once.

Stopping a run. Cancel stops a run on the page at once, even in the middle of a long step, and keeps nothing it had half-written: no part of a file is offered. In a workflow, the step is then Stopped by you, to run again. For a moment afterwards the page may say “The cancelled run’s files are still being released; try again in a moment.” On the command line, Ctrl-C stops a run in the same way, and removes its working files and any file it had not finished.

The file you chose, kept¶

While Keep my working data between visits is on (in the Permissions panel, under Your working data), the file you choose on the main page, or the files, is kept in this browser, with no time limit, so that you need not choose it again. It stays until you forget it, clear a workflow’s files (Clear them), turn the setting off, or choose another file, which takes its place. It never leaves your computer.

On a new visit, or after a reload, it is offered above the place where you choose a file, never chosen for you: Kept from last time: …, with Use it and Forget it. Taking up a workflow again, or a reload for a permission while Chora has it open, chooses it again by itself. The Permissions panel lists it too, with Forget it. Like everything else kept in this browser, it can be read by other pelagios.org pages on this computer (see who sees what).

Checking¶

Check holds a file to PLATO’s own definitions. A JSON document is checked against PLATO’s JSON Schemas; spreadsheet tables against their table definitions, and against the rules those definitions cannot state, such as that a relation names a place or something else, one or the other; linked data against the terms the ontology defines. It also finds two mistakes no schema can: a route or network that, through its members, is a member of itself; and an identity match written under one place that names another place as its subject.

The report comes in three parts:

  • Problems must be put right before the data is valid PLATO. Each is named in plain words, with where it is: the sheet, row and column, or the place and the key.

  • Warnings are worth a look, but the data can still be used.

  • Would not be carried over lists what PLATO JSON has no place for, should you convert the file.

A file that stops part-way, or is damaged, is reported as a problem in the file, with what could be read before it.

Converting¶

PLATO JSON and linked data hold everything PLATO can say, and converting between them loses nothing. The spreadsheet tables and Linked Places Format hold less, by design: see what the spreadsheets cannot say. Two rules govern what PLATO tools does about that.

Nothing is left out without saying so. The report names everything the target format has no place for, in words (“The pronunciation of a name…: Linked Places Format has no place for this, so it is left out”).

Nothing is written that would mislead. Where leaving a detail out would change what a statement says, the whole statement is left out, and the report says so:

So a file in the tables or in Linked Places Format shows the dataset as it stands now. It never shows a withdrawn statement as current, a denied market as a market, or one figure from a table as a fact about the whole place.

Web addresses for your identifiers. PLATO fixes how the spreadsheet tables’ identifiers become web addresses, so that every tool gives the same ones. The base is the one given for the conversion, if any (on the page, “Web address for your identifiers”), and otherwise the base_uri of the about sheet, which is where it belongs; a / is added to it unless it already ends in / or #. A place’s address is the base, then place/, then its place_id (https://w3id.org/my-project/place/bristol), and a source’s is the base, then source/, then its source_id. In both, every character other than a letter, a digit or one of - . _ ~ is percent-encoded (written as a code such as %20), so keep identifiers to those characters. The dataset’s own address is the about sheet’s dataset_uri, or the base (with its /) if that is empty. Without any base, PLATO tools uses a stand-in, https://example.org/my-dataset/, which is not a permanent address. Converting to the tables, an address is kept only if reading the tables back would give the same one; otherwise the report says it is lost.

Gzipping the output. Under Options, Gzip the converted file compresses the file as it is written and adds .gz to its name; on the command line, give --gzip to convert (it is for converting only). The same data always gives the same bytes. The spreadsheet tables are not gzipped, as they are a zip already, and the report says so.

Comparing two versions¶

Once a dataset says it is published, its attestations are only ever added to: none is deleted or changed, and a correction is a new attestation that withdraws or replaces the old one, which stays. Why, and what that makes possible, is explained under citing a place in a gazetteer that changes.

Compare with the earlier version shows that a new version has kept to this. Choose the new version first, then press the button and choose the earlier one. The two may be in different formats: what is compared is what each attestation says, not how the file writes it.

Problems are what breaks the rule:

  • an attestation of the earlier version that is missing from the later one;

  • an attestation that says something different in the later one;

  • an attestation that says the same but has lost its web address, or has been given another: later statements point to it by that address;

  • a name, location, date, type, property or citation, with a web address of its own, that attestations point to, and that the later version describes differently, or no longer describes at all though attestations still point to it. It is part of what those attestations say, so changing it changes them;

  • a pair of places that one contributor now says both are and are not the same place, with both answers current: a decision was changed without withdrawing the earlier answer (see reviewing matches).

For the first few attestations, names and other facets that changed, the report shows what changed: what one version says and the other does not. Each problem says how to put it right.

Warnings do not break the rule:

  • a place or a source described differently, since those may be corrected;

  • an identity match removed or changed;

  • an attestation added without the date it was made (created), without which the dataset’s state at an earlier moment cannot be worked out;

  • a later version that is not marked published, gives the same version as the earlier one, or names another as the version before it.

Before the earlier version is published the rule does not yet apply, so everything is listed as a warning, and the report says why.

Give your attestations web addresses. An attestation without an address of its own (in JSON, an @id) can only be found by what it says. If one goes missing, the check cannot tell whether it was deleted or changed, and no later attestation can withdraw or replace it, since there is nothing to point to. The report counts such attestations. PLATO recommends that every attestation in a published dataset has a permanent address. The spreadsheet tables have no column for one, so this applies to data published as JSON or linked data.

A comparison that could not read the whole of either version does not pass, and nor does one whose earlier version holds no attestations: in both cases nothing, or not everything, was compared.

Reviewing matches¶

A match review asks, place by place: is this Newton that Newton? Choose your dataset, press Match with another dataset…, and choose the other one, in any format PLATO tools reads. Places whose names are alike, and that are near each other, are suggested as possible matches; you accept or reject each, and your decisions are written as attestations, like any other. Matching two files on your computer sends nothing anywhere.

A suggestion is a claim by no one until a person decides (see candidate sets), so none goes into your dataset: only your decisions do. For each suggestion, choose one of:

  • Same place: the suggestion is your place. The matches you accept for one place are written together as one attestation, so they stand or fall together.

  • Not this one: the suggestion is wrong, and there is no more to say. Nothing is written.

  • Different places: you can say why the two are not the same place. Your reason is written with a denial: an attestation that the two are not the same place.

A candidate whose kind of place clashes with yours (a lake for a town) is placed after the others, and says so (Ranked down: …). It is never left out. A place of the other dataset you have already accepted for another of yours says so too (Already accepted for …), and can still be accepted, since two of your places may be one.

Save the review keeps the suggestions and your decisions so far in a file of their own, the work file. To carry on, choose the same dataset, press Resume a review… and choose the work file. It is yours: a working file of PLATO tools, not PLATO data, and it is not published.

When you have done, press Finish. By default you get your dataset with the new attestations added, as a PLATO JSON document, offered to save only once the version check has found nothing of the original deleted or changed. Or you can choose a PLATO file of only the new attestations, each naming its place by its web address.

Changing a decision after Finish. Every attestation the review writes is given a web address of its own, made as Mint makes one (#a- and a hash: see addresses), so that a later change can point to it. This applies only to places under the dataset’s base address. Finish again after changing a decision, on the dataset that Finish wrote, and the earlier answer is withdrawn: a new attestation retracts it (plato:Retracts), and the new answer, if there is one, is written beside it. Nothing is deleted, so the dataset still shows what it said before. A decision made again unchanged writes nothing new. Only your own earlier answers are withdrawn. They are recognised by your ORCID iD, or by your name alone where either side gives no ORCID iD, and the report then asks you to check them. PLATO tools never uses plato:Supersedes for this: a superseded answer would come back if the answer that replaced it were withdrawn later.

In a dataset not yet published, the Finish area also lets you replace the earlier answer: take it out and write the new one, keeping no record of it. Withdrawing is the default. A published dataset always keeps its earlier answers, whichever you choose. On the command line this is --draft-answers withdraw or replace.

Each Finish is recorded in the work file: what it wrote, and by whom. Save the review again afterwards, as the page asks. A later Finish can then tell whether you have given it the dataset it wrote. If you give it the original file instead, which holds none of the review’s answers, it warns you, since a changed decision cannot withdraw an answer that is not there.

Looking places up in the World Historical Gazetteer. The review can also look your places up in the World Historical Gazetteer (WHG), or another gazetteer that offers the same kind of search, online and only if you choose. You allow the lookup in the Permissions panel of PLATO tools, and give a WHG token of your own (see the WHG token, below). A preview shows exactly what will be sent before anything goes: each place’s name, its other names only if you ask, and its coordinates only if you choose to search near it; and, where a Scope is set, which of its parts are sent and as what; nothing else of your dataset. What comes back joins the review beside your own matches, with each record’s licence and its kind of place, nearest first. A candidate whose kind of place clashes with your place’s own (a lake for a town) comes after the others as near, and says so (“Ranked down: …”). Your place’s own kind decides the order only among records of one place (within 2 km of each other), as when WHG holds one village several times over, from different gazetteers. WHG’s scores rank the answers to one search only, not how likely a match is, so the decision is still yours.

Which places are looked up is chosen in the lookup panel; Only places without a gazetteer link chooses, in one click, the places that neither have a gazetteer’s address of their own nor are linked to one, and the preview says how many before anything is sent.

A place whose own address is already a gazetteer’s (a WHG, GeoNames, Getty TGN, Wikidata, OpenStreetMap or Pleiades address, such as a TEI ref or a Recogito link) keeps it: it is never replaced, and WHG’s record of it is not suggested again. It is still looked up, and if WHG’s best candidate is more than 25 km from the record its address names, the place is flagged on its review screen with both records and the distance. A flagged place is left for you to decide, and never accepted in bulk. The distance can be changed in the lookup panel. Where WHG did not return that record, or the record has no point, the screen says so and nothing is flagged.

Kind of place. Each candidate from the World Historical Gazetteer shows Kind of place: with its types: a type from the Getty AAT by WHG’s label for it, with its code, and any other source’s type as its code alone (such as gn:P.PPL or osm:village), never a label made up for it; or type unknown when the record gives none. Your place’s own kind is the types your dataset gives it (in a table of places, its kind-of-place column). Some kinds never go together, such as a body of water and a settlement; a settlement, a division and a landform do (a parish named after its village, a village after its hill), and a kind these tools do not know decides nothing. Chora’s Find in a gazetteer… panel shows each record’s kind in the same way, naming by label only the types of Scope’s shortlist.

Placeholders. WHG holds some records whose only name is a cataloguing placeholder (“Oknoname 037068 Dam” and the like). These are left out of the candidates, and the lookup says how many, in its summary and on a place left with nothing.

WHG’s limits. WHG allows each token a number of requests a day. When it is reached, the lookup stops, keeps what was answered, and says so: “WHG’s daily limit for this token is reached; it resets at …”, in your own time. Your token is not at fault, and is not asked for again: resume the lookup once the limit has reset. WHG’s limit per minute is waited out by itself.

The WHG token. The field for it, Your WHG token, shows only when the World Historical Gazetteer is the service chosen, in the lookup panel and in Chora’s Find in a gazetteer… panel, which share it. Before a token is given, the field is empty, with Remember my token beside it. Press Enter to give the token for this tab only, or Remember my token to keep it in this browser. Once a token is given, the field shows ••••••••, never the token itself, with where it is kept beside it, Token kept for this tab only or Token remembered in this browser, and Forget the token, which forgets it in this browser at once, without asking. Forgetting a token does not revoke it: only regenerating it in your WHG profile does. The field takes only what you type or paste into it: a password your browser has saved is never taken for a token. The Permissions panel says where the token is kept too, and can forget it.

The language of the names. Each name is sent to the World Historical Gazetteer with its language, so that WHG reads it as a name in that language: the name’s own language tag where it has one (en-GB is sent as en, eng as en), else the language you give for the whole dataset in the lookup panel (The dataset’s language, a code such as en, la or ang; on the command line, --lang). You need not know the code: type a language’s code or its name, and the field offers the languages that fit, historical ones among them, so that old eng finds Old English, ang. A code the field does not recognise is refused beside it, and nothing is sent until it is corrected or emptied. A name tagged und or mis takes the dataset’s language; one tagged mul or zxx is sent with none. A name with no language is never sent as “undetermined”, and the preview says how many queries go without one. A language is not a filter: it leaves nothing out.

Regions are matched to areas. In the region review, each region is looked up among records with an outline only, so that a region is never matched to a point (a town of the same name), within which nothing could be looked up. The places themselves are looked up among all records.

Wikidata items for the places no gazetteer knows¶

A place the review leaves with no match (every candidate judged Not this one or Different places, or none found) can be given an item in Wikidata, with its names, a description, its kind of place, its point, its country and, from the region review, the region it lies in; the new item then comes back as an identity of the place. The panel for it, Wikidata items for the places no gazetteer knows, is under the review, in five parts, in order. In a workflow it is an optional step of its own, after the review (see Map your data, step 6). PLATO tools never writes to Wikidata: it writes a batch, which you run with your own Wikidata account.

  1. Search Wikidata first. Before an item is made, each place with no match is searched in Wikidata itself, by each of its names in its own language and, where it has a point, for items within 5 km of it, which sends its coordinates. The search needs your permission for Wikidata in the Permissions panel, and no account or token; the preview says what will be sent. What it finds joins the review as candidates, which are never accepted in bulk: decide each (Same place records the item found; Not this one or Different places lets the place go to the batch). A place never looked up in the World Historical Gazetteer is counted and warned of, not refused: look it up first, so that an item is not made for a place a gazetteer knows.

  2. The licence. Wikidata’s data is in the public domain (CC0), so the dataset’s licence decides whether its statements may go there. A dataset in the public domain (CC0, the Public Domain Mark, PDDL) passes. One under a licence that asks credit or share-alike (CC BY, CC BY-SA, ODbL, ODC-By, the Open Government Licence) needs your statement, I hold the rights in this dataset, or have the holder’s permission, and release these statements under CC0, recorded with your name and the date, for that licence: change the licence, and it must be made again. A licence that allows no commercial use or no adaptations, a rights statement, no licence, or one these tools do not know, refuses the batch. A statement taken from a cited source that is not free to copy is left out of the item, and the panel says so.

  3. The items. A place qualifies when it is reviewed (no candidate left undecided), matched to nothing, linked to no gazetteer record, searched in Wikidata and answered, with a web address under the dataset’s base address, a name, a point (or a region the region review matched to a Wikidata item) and an attestation citing a source; the panel lists each reason a place is left out. Each item has labels (the name in each language) and aliases (the other names); a description, filled in as “ in , , attested –” and yours to edit (two to twelve words); Instance of (P31) from its kind of place, or one you choose; Coordinate location (P625), to as many decimals as the location’s precision allows; Country (P17) from its country code; and Located in (P131), only from a region the region review matched to a Wikidata item. No dates are written. Each statement is a tick-box, and Leave this place out keeps a place from the batch.

  4. The batch. Download the QuickStatements batch writes the items as QuickStatements text (its version 1 commands), named after the dataset with .wikidata.qs.txt, each statement referenced to the place’s own web address and the date. One batch holds at most 250 items: for more, leave places out, or ask for Wikidata’s approval first (Requests for permissions/Bot), talk to WikiProject Historical Place, and make the batch in parts. A dataset not yet published is warned of, not refused, since the addresses the batch cites may not lead anywhere yet. Then open QuickStatements and log in with your Wikidata account (it needs to be autoconfirmed: at least 50 edits, and four days old); choose New batch, then V1 commands, paste the batch and Import V1 commands; check the commands, and Run them. Keep the batch number: the batch is an edit group, which can be undone whole.

  5. The Q-ids back. Paste the Q-ids of the new items (one a line, in the batch’s order, or the table QuickStatements shows) and press Check the Q-ids; or give your Wikidata user name (sent to Wikidata only) and press Read my new items. Each item is read from Wikidata and checked against the batch’s row: a label equal to one of the place’s names, its point within 1 km where the place has one, and the reference to the place’s address. A verified item is recorded in the review as an identity, which Finish writes into the dataset, citing Wikidata (the version check sees only an addition); an item not verified is shown, never recorded. Take the Q-id out lets the place be given an item again. Save the review afterwards, as the page asks.

On the command line the same parts are wikidata search, wikidata batch and wikidata ids, over the review’s work file: --allow-host wikidata is the consent to ask Wikidata, --consent the rights statement, and the Q-ids come from a file (--qids) or your own new items (--user):

npx github:pelagios/plato-tools wikidata search places.json --review places-review.json --allow-host wikidata
npx github:pelagios/plato-tools wikidata batch places.json --review places-review.json --consent
npx github:pelagios/plato-tools wikidata ids places.json --review places-review.json --reviewer "Your Name" --allow-host wikidata --qids qids.txt

Scope: confining every lookup¶

A Scope confines every lookup in the World Historical Gazetteer to a part of the world, kinds of place, years and sources. It is sent to WHG only; another gazetteer is sent nothing of it. Edit opens it in the centre of the page, under Scope of the lookups, in four parts:

  • Where: Anywhere; In these countries; Within a place in WHG, found there by name, among records with an outline only (a point cannot hold places); or Within an area drawn on a map, drawn corner by corner on the Natural Earth map, from this site.

  • What kinds of place: chosen from a shortlist (villages, parishes, rivers and so on), or, under More types…, from WHG’s whole tree of the AAT’s place types. WHG matches a type exactly, not the narrower types under it, so each type chosen is sent with all of them, and its label says how many (“Villages (and 1 narrower type)”).

  • When: From the year and To the year, either or both (a year before the common era is negative: -500 for 500 BCE), with Include places with no dates. Unticked, a place with no dates is left out whenever years are given, and the Scope says so: Places with no dates are left out.

  • Only these sources: the WHG sources to look in, sent as their namespaces. Nothing chosen means every source. Unlike the other parts, the sources narrow WHG’s search itself.

Done goes back to the step. Clear the Scope sets it back to nothing.

Whose Scope it is. In a workflow, the Scope is the workflow’s: kept with it, in this browser and in its downloaded record, and used by every WHG lookup it makes, including Chora’s Find in a gazetteer… when Chora is opened for the workflow. It is shown as one line in the tracker, such as Scope: GB, IE · Villages · 1500 to 1600, which opens to its four parts, with Edit. Outside a workflow, the lookup panel has a Scope of its own, for that tab only. A workflow begun while the tab has one asks whether to use it (Use it or No), and never takes it in silently.

What a row already says comes first. Once the regions in your table’s region columns are matched, each place is looked up within its own regions, not within the Scope’s Where, and so are the regions below the widest. A place’s own filters in the lookup panel (its countries, near its point) win too. The kinds of place, the years and the sources still apply to every place. A place looked up before its regions are settled keeps the Scope’s Where.

A narrow Scope can leave a place with nothing. The sources narrow WHG’s search itself, but the Where, the kinds of place and the years are filters: WHG first takes its best two hundred or so matches by name, from the sources chosen, then leaves out every one outside them, the right answer too. A place for which nothing was left says so (“Nothing within the Scope among WHG’s best name matches…”), and offers Look it up again without Scope, for that place alone, with nothing of the Scope sent. Nothing is ever relaxed by itself.

Reviewing regions, level by level¶

Many tables give, beside each place, the regions it lies in: a country, a county, a parish (the columns read as within). Review the regions level by level looks these up in the World Historical Gazetteer before the places, widest first, each inside the one above it. Every row naming Surrey in England is one region; a Newport in Shropshire and a Newport in Monmouthshire are two.

How a match narrows the next search. A region waits until the region above it is settled, with a match or with None of these. Its search is then kept within the gazetteer’s record for the region above, or within all its records taken together when it was matched to more than one. Where that cannot be asked, it is kept to the area they cover. Either way, the match’s countries are added. The widest level, which has no region above it, is kept within the Scope’s Where, if one is set, and so is a region whose region above has no match. A constraint only ever takes candidates away: a country filter even drops one with no country recorded. Each region says what it was looked up within. A search WHG could not narrow returns nothing, and the review says so: that is not a finding that there is no match.

Asking again. When the right region is missing, ask again, for one region or a whole level: Again without the countries, Within the area instead, within the region above that instead, or With no constraint, which also drops the Scope’s Where (its kinds of place, years and sources still apply). Each button says how many queries and requests it will cost. Changing a settled region clears the decisions and candidates below it, after asking, and Undo puts them back. Once a place’s regions are settled, the places are looked up within them and reviewed one at a time, as in reviewing matches. A place still waiting can be looked up without its regions.

WHG’s guards. WHG’s own page accepts a candidate only when it tops its answer, its title is an exact match or its score is 90 or more, it is not held back, and there is no tie. It is held back when WHG gives it a confidence below 30, or, where WHG gives none, when its names are too unlike the name sent, by WHG’s own measure. It is tied when another candidate scores as high, unless that one is the same record repeated. In the review of places, Accept the N that pass WHG’s guards accepts each place’s one passing candidate, as the kind of match you choose (close match by default). A candidate too far from the place, in another country, or of another kind of place than yours (a lake for a town, say), is left out and counted, for you to decide: a clashing kind is never accepted in bulk. So is a place for which two places of its name were found where it was looked for, even when WHG’s guard lets one of them through: the place says so (“2 places of this name in …: left for you”). Within a region, every place of that name in it counts, however far off; otherwise only those within the greatest distance. Records of the name within 2 km of each other are taken for one place, as WHG often holds one village several times over, from different gazetteers. Only titles are compared, not other names. Each acceptance is recorded as your decision, naming the guard; Undo takes them back. Nothing is ever accepted automatically.

What is written. Two separate claims, as in regions matched to a gazetteer. Your source’s containment stays as it is: each place is ContainedIn a region made from your data, one for each whole chain of regions. Your decision is an attestation about that region, with you, the date and your certainty, bundling an identity relation (a close or an exact match, with its basis) to each gazetteer record you matched it to. When the suggestions are published as a candidate set, each relation points back to its suggestion with promotedFrom, and the suggestion’s matchParameters record what it was looked up within. The containment is never rewritten: a match changed later is a new attestation. Regions need addresses of their own, so the dataset needs a base address. The repository’s place-centric-regions.json and candidate-set-regions.json show both claims. Linked Places Format writes them as one broaderPartitive relation.

Rows set aside. A place can be marked Keep without reconciling (never looked up, still in the dataset) or Leave out of the dataset (and the version check is told to expect exactly those missing). A source with a web address of its own that only a place left out cited goes with it: Finish still succeeds, and the version check warns, naming the address, which will no longer resolve if your dataset serves it. Notes stay in the work file, never in the dataset.

From the command line. With your WHG token in WHG_TOKEN:

npx github:pelagios/plato-tools lookup --levels --dry-run parishes.csv
npx github:pelagios/plato-tools lookup --levels --reviewer "Your Name" parishes.csv

The first shows the plan, level by level, and sends nothing. The second looks up the first level with regions ready (or --level N) and writes a work file, given back with --review to carry on. --relax takes countries, area, ancestor or all; --only one region or place; --unconstrained also looks up places whose regions are unsettled. The regions are decided on the page.

Placing on the map¶

Chora, in the middle of the PLATO tools page (its card among the tools, Show on the map in step 2, or straight to it), shows a dataset’s places on a map, with everything their attestations say of each one over time, and lets you add a location you have worked out yourself: a point, a line or an area, drawn on the map, or traced from a historical map laid over it. A historical map can also be traced into a new dataset of its own, each feature a place (see tracing a map into a new dataset). It runs in your browser like the rest of PLATO tools, and reads the formats in the table above. A table of places of your own is read with its columns matched as PLATO tools guesses them; to correct the matching, convert the table to PLATO JSON first and open that.

Chora shows the file chosen in step 1, Choose your data, as soon as it opens, and whatever you choose there while it is open; it has no file chooser of its own. Step 1 stays above the map, folded to one line with Change once its file is recognised. While the map is shown, the tools fold away behind Tools ▸, which brings them back, and a workflow you are following stays beside the map. Leave the map goes back to the steps. If the map itself cannot be loaded, the page says so where the map would be, with Reload the page, which comes back to the map.

The map shows every place with a location, grouped where they crowd together (it shows the first 50,000; find others by name). Find a place by any part of a name, or click it on the map. The search looks in the name each place is listed under and in every name its attestations give it, as written and in Latin letters (toponym and romanized), except names denied or in a statement withdrawn or replaced. A place found by another name is listed with it: Byzantium — also Constantinople. Capitals and accents make no difference, and letters such as œ, æ, þ, ð and ß, and ligatures such as ﬁ, match as they are spelt out (Brabœuf finds braboeuf). The list shows fifty places at a time, with Previous and Next, and marks a place with no location recorded. A IIIF Georeference Annotation, which places a map rather than describing places, is not a dataset, and Chora says so: to lay the map over the basemap, paste it under Historical maps (see tracing from a historical map).

Chora works in one tab at a time: opened in a second tab, the map says that it is open in another, and the rest of the page works there as usual.

A place’s card lists what its attestations say: its names, types, locations, related places (click one the dataset has to go to it) and sources. Over time draws each dated statement as a bar from its start to its end, by year, and lists those dated only in words. A statement the source makes less than firmly is labelled: denied (the source says it was not so), doubted, reported (as said by others) or tentative. On the map, a place’s locations are drawn in the same colours: a firm one solid, the others dashed (a point, hollow), and a denied one, where the place is said not to be, faint.

How well a location is known is drawn too, as PLATO records it, and only where it does. A point’s precision (spatialPrecision) is a mark around it: four ticks for exact, a dashed ring for approximate, three small rings for uncertain (one of several possible locations), and the dashed ring with an hourglass for historical approximate. A line or an area outline is edged in the same way: solid, dashed, dotted, or dash and dot. A point’s precisionKm is a circle of that radius, drawn to scale on the ground, and the map zooms out to show it whole when you choose the place. A location whose precision is not given has no mark, and one without precisionKm has no circle: the map does not invent an uncertainty the data does not give. Key: how well a location is known, folded at the foot of the map once a place is chosen, shows each mark. The card names the precision with PLATO’s own gloss, and how far out the location may be (“to within 2 km”; for a line or an area, “boundary to within 2 km”). Where the circle would be too large to draw, the card adds “(too large to draw)”.

A statement that a later one withdraws or replaces is left out, as PLATO requires of any view of the dataset as it stands; the card says how many were left out.

A place with no location is shown by what the dataset says about it instead: the places it is related to, if they have locations, or else the outline of its country, from its country codes (ccodes). The card says which. Where there is neither, it says there is nothing to place it by.

Drawing a location¶

Choose a place, then draw with the tools on the map: Point; Line, clicking each point and the last one again to finish; or Area, clicking each corner and the first one again to finish. Edit moves or reshapes a drawing, and Stop ends drawing. Point at a tool, or reach it with the keyboard, and it says what it does. Each drawing appears under Your drawings in the place’s card, where you can say what it marks (the whole place, a feature of it, or a point standing for it) and how well the location is known (exact, approximate, uncertain, historical approximate), or remove it. A drawing that crosses the 180° meridian, in the Pacific, cannot be recorded as it is drawn, so it is not kept, and the card says why.

Drawings are kept in this browser until you save, even if you close the page: choose the same file again, unchanged, and they come back, with their places. To keep nothing between visits, turn off Keep my working data between visits in the Permissions panel: drawings not yet saved are then cleared the next time you open Chora, so save them before you leave.

Tracing from a historical map¶

Under Historical maps, paste a georeference (a IIIF Georeference Annotation, such as one made in Allmaps), or the address of one, of a IIIF manifest or of a IIIF image, and press Add the map. The map is laid over the basemap, placed on the earth by its georeference. Where it holds several georeferences of one image, made separately, Chora lists them, each with the date it was last changed and its number of control points, and you choose one (the most recently changed is chosen to begin with). A map that comes with no georeference can be looked for in Allmaps with Look for a georeference; or you can georeference it in the Allmaps Editor, from the link that says it sends the map’s address, and paste here the georeference it makes.

Each map shown names the site its image comes from, with its credit and licence, and has Opacity, Show, Fit and Remove. A map whose licence allows only non-commercial use has one line more, saying that this may bear on how what you trace from it can be reused. The maps you add are kept between visits, as drawings are, unless Keep my working data between visits is off.

No map’s site is asked until you allow it in the Permissions panel, as for a basemap: its image server, which sees which map you view and which parts of it, and Allmaps, which learns which map a georeference was looked for. Each has its own Needs permission line under the paste box, and one reload brings them all. An address that forwards to another site, as some archives’ addresses do, is not followed: Chora offers it as a link to open in a new tab, so that you can paste the address it ends at. If your browser does not show that it enforces the page’s protection, no map is shown.

To trace a place the dataset has, choose it and draw over the map by hand, with the same tools. To make new places from the map, see tracing a map into a new dataset. A drawing on a map is traced from it (from the topmost, where maps overlap), and Traced from in the place’s card lets you choose another map it lies on, or the basemap. A traced point is, until you change it, a point standing for it, of approximate precision, since a map’s symbol stands for a place rather than drawing it: choose a feature of it where the map draws the feature itself, such as a church drawn as such. A traced drawing can also mark where the map writes its name. A drawing moved or reshaped is traced again; if it no longer lies on the map, it no longer cites it, and the card says so.

Tracing with assistance from the map’s ink¶

Once a map shown has drawn a tile, two more tools are offered beside the drawing tools, Trace area and Trace line; until then they say in a tooltip why not. The tracing itself is loaded when one is first pressed, and a click made on the map before it has loaded is acted on once it has. With Trace area, click inside an area the map draws, such as a wash or an outlined field, and its outline is proposed from the map’s own ink; with Trace line, click on a line, such as a road or a river, and it is followed both ways from the click, as far as the ink goes, and proposed. The proposal is shown on the map, with a panel of settings. For an area: the colour tolerance, Bridge gaps in the outline and how far, and Leave out small holes (lettering), which keeps holes no bigger than the map’s lettering out of the proposal. For a line: Match the colour clicked (else: the darkest ink), which follows the colour under the click, within the colour tolerance, rather than the darkest ink (the tolerance counts only when this is ticked); the thickness of line to follow; and Jump gaps in the line. For both, how closely to keep to the ink. Moving one proposes again, from the part of the map already read, so the map’s server is asked nothing more. A proposal is not yet a drawing: Accept (or Enter) makes it one, to edit or remove like any other, and Let go (or Esc) drops it. Accepting before a place is chosen keeps the proposal and asks you to choose one.

A line may stop where the ink does, or where it meets a fork it cannot judge; Shift-click further along carries it on, keeping what was proposed and tracing the new click alone. Whatever holes an area still has are left out when it is accepted, since a drawing is an outline: the page says how many. A fill that covers most of the part of the map read is refused in words, as the area is not closed: bridge its gaps, or lower the tolerance. One that runs out to the edge of the part read is tried again from a larger part, and then once at a coarser scale; if it still runs out, the page says it is too large to trace at once: zoom out, or trace it in parts.

Snap to ink, offered while you draw a line or an area by hand (not a point), once a map shown has drawn a tile, helps tracing by hand: a vertex you place within 10 screen pixels of the map’s ink goes onto it, the centre of a line or the edge of an area. Hold Alt to place a vertex where you click.

What is proposed is read from the map’s image tiles, fetched from the map’s own image server under the permission you gave it under Historical maps, and nothing else is asked; withdraw that permission and everything read from that server is let go, the proposal with it. The work is done in your browser.

A shape traced this way is attested, not computed: you accepted it. Its notes say so, after the georeference’s sentences: that it was proposed from the map’s ink, by filling an area or following a line, with the settings used; for an area, how many holes were left out; then whether it was accepted as proposed or edited by hand, counting the vertices moved, added and removed against those proposed. Moved off its map, it keeps saying how it was proposed, and that the citation was dropped.

The assistance has limits, which it is better to know than to meet. It reads the map at the resolution shown, so a fine line is best traced zoomed in: a line about three pixels wide in the image read, running diagonally, may be placed a few pixels short at its ends, and a very short stroke of that width may not be followed at all. A line narrower than six pixels that ends square-cut, but runs at a slant to the image’s pixels, has that end placed as if rounded, half a line’s width short; an end square to the pixels is placed where the ink stops. A line ending on a bar twice its width may run on along the bar; on one of its own width it stops. A map’s server that refuses its pixels (one that asks you to log in, or lets no other site read it) cannot be traced from, and the page says so. Check every proposal against the map before accepting it, as you would a drawing of your own.

Tracing a map into a new dataset¶

A map shown under Historical maps can be traced into a dataset of its own: “each feature you trace becomes a place, named as the map writes it, and cites the map and its georeference.” Press Trace into a new dataset beside the map. The panel Trace into a new dataset, below the maps, says what is under way. It is also the first step of the workflow Trace a historical map, but works without one.

Into the dataset open. With a dataset open (any but one made from a map and not yet saved), the button says Trace it into the dataset open, and the places you trace are added to that dataset, as new places of its own. They are given their addresses under that dataset’s own base address, its uriSpace, whatever Options say: the settings show it, with the dataset’s title, and neither can be changed there. Under it: The dataset open’s own base address (its uriSpace), as its file gives it: every place traced into it is given its address under it, whatever Options say. Trace into it begins. A dataset that gives no base address of its own cannot be traced into, and the panel says why: “…” does not say under what address its places are published (it has no uriSpace), so a place traced into it could not be given an address of its own. Give the dataset its base address (uriSpace in PLATO JSON, or the about sheet’s base_uri) and open it again, or trace the map into a new dataset of its own with no dataset open.

The settings for the map are asked once, and kept for that map:

  • Base address: your places will have their web addresses under it. Needed: every place you trace is given its address under it as you name it. It is the base address in Options, which this changes too. Once the dataset is made it is fixed, as is the title; traced into the dataset open, both are that dataset’s, as above.

  • The dataset’s title, to begin with Places traced from the map’s title.

  • The map’s date, as you would cite it, filled in from the map’s own date where its description gives one, and Date each place by the map: what it shows is as of then (ticked to begin with).

  • The language of the names on the map (a code: en, la, fr…), given to every name and changed for one name where it differs. Where the language is written in another script than Latin letters, The names are written in asks which: that script, or Latin letters (a romanised form).

  • What each feature marks, and how well it is known, until you say otherwise, folded: for Points, Lines and Areas, What it marks and How well known. A point stands for the place (a point standing for it), a line or an area is the whole place (a route only where you say so), each approximate. With them, An uncertainty radius of your own for this map, in km (optional), given to every feature, and said in its notes to be your estimate. The georeference’s own error is said in the notes, and never made the radius.

  • In a workflow that looks the places up, Look the places up within the map’s outline: the gazetteer lookup’s Scope becomes the area the map covers (ticked to begin with).

Make the dataset, and trace makes it and chooses it in Choose your data; later, Change the settings and Keep these settings change them, each but the base address and title still open to change for one place as you go.

What the map lets you do with it. Above the settings, and while you trace, one line says whether what you trace may be reused, from the map’s licence and its georeference’s (a georeference kept by Allmaps is CC0):

  • Free to reuse: the map is licensed …, and its georeference is licensed …., for the public domain, CC0, CC BY and CC BY-SA (and RightsStatements.org’s NoC-US and NKC);

  • Not free to reuse as it is: … This may bear on how what you trace from it can be reused., for a non-commercial or no-derivatives licence, or one In Copyright;

  • Not known to be free to reuse: … Check the holder’s terms before you publish what you trace from it., where either names no licence. A credit that says “public domain” or “no known restrictions” in words is quoted, and said not to be a licence.

Naming each place. Draw a point, line or area on the map with no place chosen, or press New place first: a form over the map asks for The name, as the map writes it, Its label in lists (a display form, not evidence: the name, unless you change it), What kind of place it is (optional: a short list of kinds, each a Getty AAT concept, or words of your own; the last chosen is offered next), The language of the name, and, where the language is written in another script, A romanised form of the name (optional). Add the place, or Enter, adds it; Cancel: let the drawing go, or Esc, drops the drawing. Add to “…” instead makes the drawing one more part of the place last named: a point added so marks where the map writes its name. A shape accepted from the map’s ink with no place chosen is named the same way.

Traced from the map lists what is traced, fifty at a time, the latest first: each with its name (or Not named yet, with Name it), its kind and shape, What it marks and How well known (marked (the map’s defaults) until you change them), Edit the name and Remove. Stop tracing ends it: a drawing with no place chosen is then let go, as before, and what was traced stays.

A dataset made from a map and not yet saved is kept in this browser, as drawings are, and offered again as Go on tracing “…”: the dataset made from it, not yet saved. If the map is no longer shown, the panel says so: add it again under Historical maps to trace from it.

What a drawing records¶

Each drawing becomes a new attestation of its place, holding one location. An attestation already in the dataset is never changed, since a correction is a new attestation, not an edit (see comparing two versions). With the location, the new attestation records:

  • who drew it (contributor): your name, and your ORCID iD if you give one. Chora asks before your first save, keeps the answer in this browser (see who sees what), and shows it as Saving as your name, with change and forget me. It is never taken from the dataset, since the person drawing is not necessarily the person who made it. A mistyped ORCID iD is caught, by its last digit, before anything is saved;

  • when it was drawn (created);

  • how it was drawn, in its notes, since PLATO has no term for this, such as “Drawn by hand on the Natural Earth basemap at zoom 9 in PLATO tools (Chora)”. A basemap you pasted in yourself is not named there, only called “a basemap pasted by the contributor”, since its address may be a private one and the notes are published with the dataset.

A drawing traced from a historical map records where it came from as PLATO sets out for a geometry traced from a map (plato:Geometry, in the ontology reference). It cites the map as its evidence (cito:citesAsEvidence), with the canvas and the area traced as the locator, and the map’s licence where it is known; and it cites the georeference as the method used (cito:usesMethodIn), as a source of its own derived from the map. Its notes begin with the georeference’s address, its transformation and number of control points, and when it was retrieved, and the canvas and manifest, since a georeference can be changed after you trace from it; then comes “Traced by hand from a georeferenced historical map at zoom 9 in PLATO tools (Chora)”, or, for one traced with assistance, how it was proposed and what was done to it by hand.

A place traced into a new dataset is written as a new place, with its label and its address under the base address (the dataset’s own, traced into one open; made from the label, with a number after it where that is taken), and one attestation holding all it was traced as: its name, with its language (and its romanised form), its kind, its geometries in the order drawn, the map’s date as its timespan unless you said not, and the map and its georeference cited as above. The map’s credit and date are on its citation, and its licence where it is known; a dataset made from a map is given none. The control points’ misfit is said in the notes, and your own uncertainty radius, if you gave one, is said there to be yours.

It has no web address of its own yet: Mint gives it one when you publish the dataset.

Saving¶

Save writes the whole dataset, not the drawings alone: every place and attestation as it was read, with the drawings added after each place’s own attestations. A dataset read from PLATO JSON Lines is saved as PLATO JSON Lines (the button says Save as PLATO JSON Lines), and the file is named after yours, ending .chora.jsonl. Anything else is saved as one PLATO JSON document (place-centric), ending .chora.json (Save as PLATO JSON); a dataset in another format is converted, and the page lists anything the conversion reported.

In the same run, the version check (comparing two versions) compares it with the file you opened, and must find every attestation there exactly as it was, every place described as it was, and exactly as many new attestations as you drew, whether or not the dataset is published. A dataset with no attestations yet, such as a list of places still to be located, can be saved too: the check then finds only your drawings, as it must. Only when the check passes is the file offered to save; otherwise the page says what went wrong, and not to use it. Problems the dataset already had are listed even when the check passes, since the saved file has them too.

Nothing is saved if a drawing is for a place whose attestations are not written as a list, as PLATO requires: the drawing could only replace them. The page names the place, to be corrected in the dataset first.

A dataset traced from a map is saved the same way, with the new places after the dataset’s own, and the version check also counts them: the save says how many places were traced from the map. Nothing is saved while a feature is not named yet: name it in Traced from the map, or remove it.

Where your browser asks where to save a file, the drawings are no longer kept in the browser once it is saved. Where it simply downloads the file, the page cannot tell when the download is complete, so the drawings are kept, and the file still offered, until you press The download is complete: let these drawings go. If you change the drawings before saving the file, it is no longer offered: save again.

Once the check passes, the saved file is also chosen in step 1, Choose your data, for the other tools, and the page says so under the save. Once its drawings are let go, Chora carries on with the saved file as its dataset, keeping the place, the view and any drawings made since, so that what you draw next is added to it and a later save builds on it. In a workflow at Chora’s step, the save also does that step, if the dataset Chora had open is the one that went to the step (see Map your data, step 8), or, in Trace a historical map, if the save adds places traced from a map. Saved from another dataset, the step stays open, and the tracker and the save say why.

Which map, and who sees what¶

The map you see first, from Natural Earth, comes from this site, so opening Chora sends nothing anywhere else. Its borders are Natural Earth’s borders as they are in practice, not a statement on any dispute.

Under Basemap you can choose another, fetched from its provider: OpenFreeMap (Liberty, Bright or Positron); Ancient World (CAWM), the Consortium of Ancient World Mappers’ map tiles, made for the ancient Mediterranean and Middle East, so that elsewhere their coasts, rivers and lakes may be missing or wrong, as the chooser says beside it; OpenStreetMap; CARTO (Positron, Voyager or Dark Matter); or a style address or tile address of your own, pasted in, including one with a key. No other site is asked until you allow it in the page’s Permissions panel. A basemap not yet allowed is not used: one line, Needs permission, opens the panel at it. The panel names every site the basemap will ask, since one provider may serve it from several, and says what they will see: the part of the world you are looking at, and your address on the internet, as any website does; never your files, which stay on your computer. There you can allow it, or allow it for this tab only, or choose Never, and it is no longer offered. A basemap allowed is used once the page is reloaded: the panel offers the reload, keeping the dataset, the place and the view, and asks first if something would be lost, such as a line half drawn. One withdrawn gives way to Natural Earth at once. A style you paste in is read from its own site once you allow that; if it names further sites, each needs your permission too before the map uses them. The page refuses any request to a site other than this one and those you have allowed, and says how many it refused. If your browser does not show that it enforces this protection, no other site is asked, and the page says so. A basemap that cannot be loaded, or none of whose tiles can be (its site is down, say, or your browser refuses its certificate), gives way to Natural Earth, which is then the basemap chosen, and the page says why: … could not be loaded from … (…), so the map is back on Natural Earth, from this site. A tile that fails among others that load does not. The Ancient World tiles are the Consortium of Ancient World Mappers’, under CC BY 4.0, and the map credits them so. They begin at the second zoom level out: zoomed out further, the map shows no basemap.

Your permissions, your choice of basemap, any address you paste (with any key in it), your name as the one drawing, the historical maps you add, your settings for tracing each map, a dataset traced from a map and not yet saved, your working data, a WHG token you ask to be remembered, and the file you last chose in step 1 (see the kept file) are kept in this browser. PLATO tools is on pelagios.org, which other Pelagios sites share, so, as the panel says, any Pelagios site can read them, on this computer only.

Adopting a location from a match¶

From a place’s card, Find in a gazetteer… looks the place up in the World Historical Gazetteer and adopts a record’s location. That records two claims, kept apart as PLATO keeps them: that this place is that record, and, as a new attestation citing the gazetteer, where it is. The search looks where the place lies: within the nearest region your dataset identifies with WHG records (its ContainedIn regions), and in its countries, and the panel says so before anything is sent. If the right record is not found there, Search everywhere looks without them; it is never done for you. When Chora was opened for a workflow that has a Scope, the search keeps to its kinds of place, years and sources, and to its Where when the place’s own regions and countries give none. The WHG token is given here as in the lookup panel (see the WHG token).

Publishing your dataset¶

Publishing a dataset means giving it addresses that will still work in twenty years, a website where people and software can find each place, and a record in a repository that gives it a DOI. PLATO tools prepares all of that from the dataset itself, in four parts. On the page, choose the part under to publish it and press Prepare; the release’s name, the previous release, the GitHub repository and the rest are under Options. From the command line, each part is publish followed by its name.

Nothing leaves your computer. Neither the page nor the command line sends anything anywhere: they write files, and uploading them, depositing them or opening a pull request is for you to do. The page gives each result as a file (a folder comes as a zip); the command line writes folders.

Every part checks the dataset first, and writes nothing to publish from a dataset that has problems. It needs to know the dataset’s base address: base_uri in the about sheet, or uriSpace in PLATO JSON. Record it there rather than giving it for each run (on the page, “Web address for your identifiers”; on the command line, --base), so that every part, and every later release, uses the same one.

The four parts, in order¶

  1. Mint writes a copy of the dataset in which every attestation has a permanent address of its own, as PLATO JSON Lines (its name ends -with-ids.jsonl). This copy is what you publish, and what the other parts read. It needs the base address (above).

  2. Report says what the dataset’s description still lacks to be FAIR: a title, a description long enough for search engines, authors with ORCIDs (whose check digits are tested), a licence given as its web address, a version, what the dataset covers, and a base address that will last. It counts the checks passed, and writes the deposit files (below). Put right what it lists, in the about sheet or the gazetteer header, and run it again. Run it on the minted copy: for a published dataset it refuses attestations without addresses. You can run it on the draft first, to see what the description still lacks before you mint. It also warns of licences that may not sit under the dataset’s own.

  3. Site makes a website for GitHub Pages from that copy, with the workflow that publishes it.

  4. w3id writes the redirect rules that send your w3id.org addresses to the site. Only for a published dataset whose base is a w3id.org address.

npx github:pelagios/plato-tools publish report my-tables-with-ids.jsonl

A release is named with --release (on the page, “Release name”); its dataset’s own address (@id) should then be the release’s, with isVersionOf the base, and the report says what to set.

While the dataset is a draft the report counts any other as a problem; once it is published its addresses are frozen, and the site lists such places as held only in the downloads.

What “published” commits you to¶

A dataset is published when its status is published. From then on:

  • its attestations are only ever added to (see comparing two versions);

  • the addresses of its places, sources and attestations are frozen;

  • minting with --previous checks the new version against the previous release, as Compare with the earlier version does, and writes nothing if anything published was deleted or changed. Against a previous release that was still a draft, it writes the copy and warns you what would be refused once that release is published.

Until then, the site says on every page that the dataset is a draft and not to be cited, and asks search engines to leave it out.

Keep it private until it is ready¶

Everything PLATO tools does to a dataset is done on your own computer: checking, converting, comparing, matching (Krisis), drawing (Chora) and preparing it for publishing (Agora). Nothing is uploaded. So the way to keep work in progress private is to keep it there: prepare, match and review it locally, and put it anywhere public only when you are ready for it to be seen.

Nothing else leaves your computer unless you allow it in the Permissions panel, and your dataset itself goes only where you send it, in a workflow’s project saved to WHG. What can go, once allowed:

  • Looking places up in the World Historical Gazetteer (Krisis’s lookup, and Chora’s Find in a gazetteer…) sends the names you look up, any limits you set (such as countries, a region, kinds of place, years or sources), and a place’s coordinates if you search near it, with your WHG token, which says who asked. The preview shows exactly what will be sent. The names of kinds of place are fetched from WHG without the token. You never need to upload a dataset to WHG to look its places up.

  • A workflow’s project saved to WHG (Projects kept in WHG) is sent whole, as a project file holds it, with your WHG token, and only when you press Save to WHG. Anyone you give its share link to can read it. See keeping the project in WHG.

  • Chora’s maps fetch their tiles and images from the sites you allow (see Basemaps); nothing of yours is sent with them.

  • A site you upload is public, even while the dataset is a draft. Every page of a draft site says DRAFT and asks search engines not to list it (noindex), but anyone who has its address can read every page and download the whole dataset, and an address is easily passed on. GitHub Pages serves a site from a private repository to everyone too (only an Enterprise organisation can restrict it), and the workflow Agora writes publishes the site on every push that changes the dataset.

So, until the dataset is ready:

  • look at the site on your own computer (npx serve my-tables-with-ids-site) rather than uploading it;

  • keep the dataset in a private repository, or in none, and commit the site’s workflow only when the site may be seen;

  • to show a draft to a colleague, send them the files.

The report and the site of any dataset not yet published say so too.

Licences that travel with what you copy¶

An attestation that copies from a source, such as a location adopted from the World Historical Gazetteer or a line traced from a historical map, comes under that source’s licence, and a dataset cannot pass it on more freely than the source allows. Chora records the licence of what it copies: an adopted location carries the licence of the source WHG had it from, and a traced drawing the licence of the map, where each is known.

So the report, on the page and on the command line, reads the licence of each source an attestation cites against the dataset’s own, and warns, with a count and a few examples (the attestation, its source’s licence and the source), of any that may not sit under it:

  • a source for non-commercial use only (NC), in a dataset whose licence allows commercial use;

  • a source whose licence allows no adaptations (ND), even under the same licence;

  • a share-alike source (such as ODbL or CC BY-SA), in a dataset under another licence;

  • a source that asks for credit (such as CC BY), in a public-domain dataset (CC0, PDDL or the Public Domain Mark).

A rights statement, from rightsstatements.org (such as In Copyright), is not an open licence: it grants nothing, and the report says that you may need the holder’s permission. A licence these tools do not know, or a location copied from a source that gave none, is reported as unknown: find out the source’s licence and record it on the source, and the report compares it. A dataset with no licence of its own is not compared at all, and the report says so.

Each warning says what to do: publish the dataset under a licence compatible with the source’s, remove those attestations (a location can be drawn again from evidence of your own), or ask the source’s holder. Each is a warning, not a problem, since only you know whether an attestation copied from its source or only cites it for a fact; and each is a reading of the licences’ terms, “not legal advice”.

The site¶

Site makes a website with a page and a JSON-LD document (.jsonld) for every place and source, at the paths the addresses above lead to, and optionally Turtle as well (--turtle). Each attestation with an address is marked on its place’s page, so its address opens the page at it. The home page describes the dataset in the form search engines such as Google Dataset Search read, and offers the whole dataset to download as PLATO JSON Lines, N-Triples and spreadsheet tables.

Beside the site, a second folder (its name ends -repo) holds what goes into your GitHub repository: a GitHub Actions workflow, .github/workflows/pages.yml, and a README-agora.md saying how to set it up. Once the workflow is committed and the repository’s Pages settings have Source set to GitHub Actions, every push that changes the dataset rebuilds the site and publishes it. The workflow runs the same version of PLATO tools that made it, so the site is made the same way every time, and publishes nothing if the dataset has problems. The site itself is never committed.

So what you commit is the copy that mint wrote, with its attestation addresses. The workflow never makes addresses: made there, they would be made again on every run, and an address that changes is no address at all. For a published dataset, the workflow stops if any attestation has no address. Before you push, look at the site on your own computer: the command line writes it to a folder (its name ends -site), which you can open through a local web server, such as npx serve my-tables-with-ids-site.

If the dataset is not at the top of your repository, say where it is with --dataset-path. The page cannot tell which folder spreadsheet tables were chosen from, so for tables it guesses, and says so: correct the path in the workflow, or make the site from the command line.

Size. GitHub Pages serves at most 1 GB for a site, and gives up on a deployment that takes more than ten minutes. PLATO tools estimates the site’s size before it writes anything. Past the limit the page stops and says what to do; the command line writes the site anyway, with a warning, for hosting elsewhere. To stay within it, leave out Turtle, or publish a subset of the places with --only, a file listing their identifiers, one to a line:

npx github:pelagios/plato-tools publish site my-tables-with-ids.jsonl --repo my-project/my-gazetteer --only places-to-show.txt

The addresses of the places left out lead to the site’s “not found” page, which points to the downloads, where every place is.

How long your addresses last¶

That depends on the base, and the report grades it:

  • A w3id.org address (https://w3id.org/my-gazetteer/) passes. It is a permanent redirect: if the site ever moves, the rules are changed and every address still works.

  • A domain of your own (https://gazetteer.example.ac.uk/) is a warning: the addresses last as long as you keep the domain and its site. When the base is at the root of the domain, the site carries the CNAME file GitHub Pages needs; set the same domain in the repository’s Pages settings and point the domain at GitHub as GitHub’s documentation says. GitHub Pages serves a custom domain only from the root of a site, so a base further down the domain gets no CNAME, and the report says why.

  • A GitHub Pages address (https://my-project.github.io/my-gazetteer/), a local one or a stand-in such as example.org is a warning while the dataset is a draft and a problem once it is published. A github.io address changes if the repository is renamed or moves to another owner, and every citation of it breaks. Use it to try things out; publish under a w3id.org address instead, with the site still on github.io behind it.

Registering a w3id.org address¶

w3id.org gives permanent addresses by redirecting them, under rules kept in a public GitHub repository, perma-id/w3id.org. A new name is added by a pull request there. w3id writes everything that pull request needs, into a folder whose name starts w3id-, and only for a dataset that is published and whose base is a w3id.org address. It needs the GitHub names of the people who will look after the name (--maintainer, once each; “w3id maintainers” on the page), and where the site is: the repository (--repo), or the site’s address if it is somewhere else (--site-url).

The folder holds the rules and a README for w3id.org, the pull request’s title and text (PULL_REQUEST.md), a list of real addresses of the dataset with what each should answer, and a script, test-w3id.sh, that asks for each. STEPS.md goes through it in order:

  1. Test the rules on your own computer before anything else, in a local copy of the web server w3id.org runs (with Docker), with sh test-w3id.sh http://localhost:8080. Every line should say PASS.

  2. Open the pull request yourself, from your own GitHub account, with the test results pasted into its text. PLATO tools never opens it: once it is merged, the addresses are public and meant to be cited for good.

  3. Once it is merged, test the live addresses: sh test-w3id.sh.

The rules send a browser to a place’s page and any other client to its JSON-LD, and a request for .jsonld, .ttl or .html to that file. The site must be live before the rules are merged, since they only send people there.

Following a workflow: Methodos¶

Methodos is the part of PLATO tools that leads you through a whole workflow, step by step, with your place kept. It does no work of its own: each step is one of the tools described above, named with what it does, and Methodos keeps track of which steps are done. The workflows are named in plain English; the tools keep their Greek names.

The tracker¶

On a wide screen the main page has three columns: the tools on the left, the step at hand in the centre, and, on the right, a column that stays in view as you scroll. A workflow you follow is shown there, under Your workflow, as a list of its steps, each with a checkbox, the tool that does it, and what it does. A step’s box is ticked once the step is done; the step at hand is marked with a ring; the steps still ahead are greyed until they are reached. A step the tools cannot do yet has a dashed box, with the reason beside it. It is skipped, not counted among the workflow’s steps, and never refused: the workflow goes on without it, and its end says what was not done. On a narrower screen the page has two columns, the tools’ cards below the steps; on a narrow one, such as a phone’s, a single column, with the tracker folded into a strip at the top of the window, Step n of N: … ▾, that opens to the whole of it. When a Scope is set, it is one line after the tracker’s buttons.

While you follow a workflow, the page’s own step numbers are hidden, so that there is one numbering: the centre is titled with the workflow’s, Step n of N: …. The file you choose in Choose your data folds to one line, its name and size, with Change to choose another. A step’s result stays in view, labelled Result of step n: …, until you act on the next step; it is then folded into its step’s row in the tracker, with Show its result to see it again.

The workflow begins when you choose its file in Choose your data (or with Choose the file in the tracker). Trace a historical map begins at once, since it starts from no file: its dataset is made in Chora. Steps are of two kinds:

  • Done by the tools. You run the step’s tool on the page, as you would without a workflow, and the step is done when the run finishes. The run must be on the step’s file: a run on another file is not counted, and the tracker says which file to choose. A run that finds problems is Stopped, one that goes wrong Failed, and one you stop Stopped by you; in each case, put it right and run the step again.

  • Yours. The tracker says what the step waits for (matching the columns, deciding on the candidates, drawing in Chora). When you have done it, press This step is done. Chora’s step needs no button: saving there does it (see Map your data, step 8, and Trace a historical map).

Back a step undoes the last step done, so that it is to do again. Leave the workflow ends it and lets go of everything Methodos kept for it in this browser. A workflow chosen but not yet begun can be let go with Discard this workflow.

Map your data¶

From a list of place names to places identified in the World Historical Gazetteer, located, checked and written out, and published if you say so.

What you need first. The lookups in the World Historical Gazetteer need an account of your own with WHG, enrolled in WHG’s beta, and a WHG token. That covers the regions in step 4, the places in step 5, and finding a record whose location you adopt in Chora. To get the token, sign in at whgazetteer.org with ORCiD, open your Profile and generate an API Token. You give the token in the lookup panel (see the WHG token). The rest of the workflow needs no account. A Scope, set from the tracker, confines every lookup the workflow makes.

The questions under 3 are:

  • Does the table say which region each place is in (a parish, a county)?

  • Will you draw or trace places that the gazetteer cannot locate?

  • Will you publish the result? (asked only when you wanted places on a map)

  • Will you create Wikidata items for the places no gazetteer knows (a batch you run in QuickStatements yourself)? Asked last, and no unless you answer yes (see Wikidata items).

  • When the table gives regions, or you will publish, Under what base address will your places, and any regions, have web addresses of their own? Where the table gives regions it is needed, since the regions are given addresses under it, so Follow waits for it; otherwise it is optional (see the base address).

The steps, with the tool that does each:

  1. Hermes: Match the columns to PLATO. Yours: match the table’s columns to PLATO’s fields in the Columns panel (see your own table of places), then say the step is done.

  2. Elenchos: Check the table. Run the check.

  3. Metaphrasis: Make a PLATO dataset of it. Run the conversion to PLATO JSON. Where the table gives regions, the conversion uses the base address you gave (it is the one in Options, Web address for your identifiers): the regions are made from the table when it is converted, and need it to have addresses of their own (see the base address).

  4. Krisis: Identify the regions, the widest first. Only if the table gives regions. Yours, in the region review (Review the regions level by level): the regions are looked up level by level, from the widest, each level within the match of the level above. The step is done only when every region is settled. The detail of the region review is in reviewing regions, level by level.

  5. Krisis: Look the places up in the World Historical Gazetteer. Where the table gives regions, the places are looked up within their regions. The workflow’s Scope, if one is set, applies too: its kinds of place, years and sources to every place, and its Where to a place whose regions say nothing of where to look. The lookup needs your WHG token and your permission (see reviewing matches).

  6. Krisis: Decide which candidates are the same place. Yours: review the candidates, as in reviewing matches. If you said you would create Wikidata items, Krisis: Create Wikidata items for the places no gazetteer knows follows, an optional step of its own. Yours: with the review open, use its panel Wikidata items for the places no gazetteer knows (see Wikidata items), then press This step is done. The step is done with the review as it stands, whether or not an item was recorded, and the next step writes any Q-id recorded into the dataset as an identity.

  7. Recording the decisions, by Finish in the review, as one of:

    • Krisis: Record the decisions in the dataset, where the table gives no regions;

    • Krisis: Record the decisions, with the region each place is in, where it does. Export the candidates first (Export the suggestions as a candidate set), so that each identity records the candidate it answers (promotedFrom). The places stay ContainedIn the regions made from the table, and each region gets your identification of it with the gazetteer’s record, as described under what is written. If the base address in Options is no longer the one the review was saved with, Finish says so, and still writes, for the review’s own address: set Options back if your places keep that address.

  8. Chora: Draw or trace the places still without a location. Only if you said you would. Yours: Open Chora, in the tracker or under the step’s title, opens Chora on the step’s dataset, with the workflow still beside the map. Draw or trace the places there, or take a location from a gazetteer’s match (Adopt: see adopting a location from a match), and save the dataset. Once the save passes its check, the step is done with the file it wrote, which is also chosen in Choose your data, and Chora says so: Leave the map to carry on. A save made from a dataset other than the one that went to the step does not do it, and the tracker and the save say why. To use a dataset saved some other way, choose it in Choose your data and press This step is done. This step is done with the dataset that went to Chora, unchanged, is refused, since nothing drawn there is in it; if there was nothing to draw, press Nothing to draw: go on with this dataset.

  9. Elenchos: Check the result.

  10. Mneme: Compare the result with the dataset made from the table, as in comparing two versions.

  11. Metaphrasis: Write it out, in the format the workflow was given (PLATO JSON). The dataset is PLATO JSON by now, and a file is not converted into its own format: the step says Ready to download, with a Download button for the file chosen in Choose your data, and is done once you have downloaded it. A dataset in another format is converted, as any step done by the tools.

  12. Only if you will publish, the four parts of publishing your dataset, by Agora: Give every place and source a permanent address, Write the FAIR report, Build the web site and Write the permanent-address rules.

Places from an edition (TEI), and Places from Recogito¶

From the place names of a TEI edition, or the places linked in a Recogito export, to places identified in the World Historical Gazetteer, located, checked and written out, and published if you say so. Choose the edition, or the export (with the IIIF georeferences of its maps, and their manifests, if it has regions drawn on maps), in Choose your data. The questions under 3 are Map your data’s, less the regions, since neither an edition nor an export says which region each place is in: Will you draw or trace places that the gazetteer cannot locate?, Will you publish the result? (asked only when you wanted places on a map), and, if you will publish, the base address, which is optional.

The steps are Elenchos: Check the edition (or the annotations), Metaphrasis: Read its place names into a PLATO dataset (or Read the places they link into a PLATO dataset), and then Map your data’s from step 5, as where the table gives no regions: the lookup, the review, Record the decisions in the dataset, Chora if you said so, the check, the comparison with the dataset made from the edition (or the annotations), writing it out, and Agora’s four parts if you will publish.

A place’s ref in the edition, or its link in Recogito, stays its own address: the lookup looks for it in WHG beside that address, never replaces it, and flags it when WHG’s best candidate is far from it (see reviewing matches). Pleiades addresses are read as a gazetteer’s like the others. The tracker lists what each reader cannot carry, such as a place name with no ref, coordinates in a name’s own <geo>, or a Recogito region on a map with no georeference.

Match two datasets¶

Your places matched with the places of another dataset, the decisions recorded, checked and written out, and published if you say so. Nothing is looked up online.

Your dataset is the one the decisions are about. Choose it in Choose your data. It can be a table of places (CSV or GeoJSON), which is read as Map your data reads one: Hermes: Match the columns to PLATO, Elenchos: Check the table and Metaphrasis: Make a PLATO dataset of it. Or it can be a dataset already in a PLATO format, which is checked (Elenchos: Check your dataset) and taken as it is.

The other dataset is not asked for at the start. You choose it at the match step (Krisis: Find the places of yours that may be the same as places of the other dataset), in Match with another dataset…, in any format PLATO tools reads, and the workflow records it as it records your dataset. Until then the tracker says it is not yet chosen. Once it is recorded, a match with any other file is not counted. Forget with its name lets it go, but only while no step has been done with it. Its places must have web addresses of their own, since a decision names both places by address. The match counts the ones that have none. A project of this workflow holds both files as your own, unless you untick Put my own files in it.

Its faults. After the match, Elenchos: Check the other dataset. What the check finds is shown in the step’s row (Done, with a report) but does not stop the workflow, since the other dataset is not yours to correct. A file the tools cannot read stops the match.

Then Krisis: Decide which candidates are the same place, as in reviewing matches, where a candidate of another kind of place than yours is ranked down and a place you have already accepted for another of yours says so. Open the review reopens the match’s review if it was put away. A review made with other files is not counted. If you said you would create Wikidata items, Krisis: Create Wikidata items for the places no gazetteer knows follows the review, as in Map your data, step 6.

The questions under 3 are:

  • Add the decisions to your dataset, or keep them in a file of their own about it? Add them to my dataset (the default) writes your dataset with the new attestations added. It is then checked and compared with your dataset, as in comparing two versions. Keep them in a file of their own writes a PLATO file of only the new attestations. It is checked, but not compared, since it is not a version of your dataset. Choose the same under Finish in the review (Your dataset with the new attestations added, or A PLATO file of only the new attestations): a Finish that makes the other is not counted.

  • Will you publish the result?

  • Will you create Wikidata items for the places no gazetteer knows (a batch you run in QuickStatements yourself)? Asked last, and no unless you answer yes (see Wikidata items).

  • The base address, which is optional. For a table it is always asked, since your places are given their addresses under it. For a PLATO dataset it is asked only if you will publish.

Publishing. If you will publish, export the suggestions first (Export the suggestions as a candidate set), so that each decision records the candidate it answers (promotedFrom). Finish is not counted until you have. Then come Metaphrasis: Write it out and Agora’s four parts, as in Map your data.

The tracker lists what the match cannot do, among them:

  • Places are matched by their names, and only within 50 km of each other where both have a location. Each of your places is given at most its five best candidates. The distance, and how alike two names must be, can be changed in Krisis’s options. Nothing is accepted in bulk.

  • “Measured with the command line (in Node, not in the browser), with 50,000 places in each dataset (constructed ones), the match took about 65 seconds on a laptop of 2024 and held under 500 MB; larger datasets are not refused, but are unmeasured.”

Trace a historical map¶

A georeferenced historical map, its places traced in Chora into a new dataset of their own, checked, identified in the World Historical Gazetteer if you say so, written out, and published if you say so. Each feature you trace becomes a place, named as the map writes it, citing the map and its georeference.

It begins from no file. Follow starts it at once, at its first step, Chora: Trace the places from the map, into a new dataset. Open Chora, in the tracker or under the step’s title, opens Chora. Add the map under Historical maps, then press Trace into a new dataset beside it, as tracing a map into a new dataset describes. Chora makes the dataset, and saving it there does the step, with the file it wrote, which is also chosen in Choose your data. Only a save that adds places traced from a map does it; any other is refused, and the tracker and the save say why. To use a dataset you traced and saved before, choose it in Choose your data and press This step is done.

The questions under 3 are:

  • Will you look the places up in the World Historical Gazetteer, to identify each with a record there?

  • Will you publish the result? (asked only when you wanted places on a map)

  • Will you create Wikidata items for the places no gazetteer knows (a batch you run in QuickStatements yourself)? Asked last, and no unless you answer yes. The step runs only if you also look the places up, since it follows the review (see Wikidata items).

  • The base address, which is needed, since every place is given its web address under it as you name it, so Follow waits for it. Under the field: Needed: every place you trace is given its address under it as you name it. (See the base address.)

If you look the places up, the steps after Elenchos: Check the dataset traced are Map your data’s, as where the table gives no regions: Krisis: Look the places up in the World Historical Gazetteer, within the map’s outline, Krisis: Decide which candidates are the same place, Krisis: Create Wikidata items for the places no gazetteer knows if you said you would (see Map your data, step 6), Krisis: Record the decisions in the dataset, Elenchos: Check the result, and Mneme: Compare the result with the dataset traced. The lookup needs a WHG token, as Map your data’s does (see Map your data, What you need first). Unless you untick it in Chora’s settings for the map, the map’s outline is made the lookup’s Scope, so that the gazetteer is asked only for places within it; Chora says so, and the tracker shows it in its Scope line, where it can be changed. Before you follow it, the workflow says: “Looking the places up uses the World Historical Gazetteer’s allowance of requests: its cap is 5,000 requests a day per token, and the lookup says before it sends how much of that it would use. A map of many places may be looked up over more than one day, the lookup resuming where it stopped.”

Then Metaphrasis: Write it out (PLATO JSON), and, if you will publish, Agora’s four parts, as in Map your data. The dataset made from a map is a draft, with no licence of its own: the map’s licence is given on each citation of the map, and the dataset’s is yours to give before you publish (see licences that travel with what you copy).

Make an open map¶

A plain map of ancient places, made from a list of their names, to illustrate an article on Wikipedia: labelled, with a scale bar and its sources written in, under a licence Wikimedia Commons accepts. No GIS is needed.

You need: a list of the places’ names (or a spreadsheet of them, or a dataset already in PLATO), a base address for your places (any web address of yours, such as https://example.org/my-map/), and a World Historical Gazetteer token for the lookup (see Map your data, What you need first).

  1. Say what you have. On the tools’ page, choose Not sure where to start? Answer three questions. Say you have A list of place names, and that you want A map image for Wikipedia or Commons. Give the base address. Follow the workflow.

  2. Paste the names. Under Choose your data, open Or paste a list of names and paste one name on each line. They are read as a small table: each name, and an id made from it. A name in Greek or Cyrillic is given an id in Latin letters (Ἀθῆναι gives athenai); the name itself stays as you wrote it.

  3. Identify the places. The workflow takes you through the tools: the columns are matched, the list is checked and made a dataset, and the names are looked up in the World Historical Gazetteer. Decide which candidate is the place you mean (accept the clear ones together), and record the decisions (see reviewing matches).

  4. Locate them. Recording a decision says which place it is, not where. Open Chora (the map): for each place, Find in a gazetteer…, and adopt its match’s location (see adopting a location from a match). Save, and say the download is complete.

  5. Make the map. In Chora, frame the view: what you see is what the map shows. Under the places, choose Make a map of this view. The preview over the map is the file as it will be written.

    • Background: Natural Earth (public domain, drawn as vectors) is the plainest; tick Shaded relief for the land’s shape, and Seas named or Mountains, deserts and other regions named if you want them. Modern borders and names are off. The Ancient World (CAWM) and Roman Empire (DARE) basemaps are pictures of ancient landscapes; DARE makes your map CC BY-SA. A historical map you have added in Chora can be the background too: if its rights are not clear, say what they are (a map published more than 120 years ago is usually in the public domain, and that is chosen for you when its date says so). If its holder licenses its scan for non-commercial use only, nothing is chosen: choosing a statement then says the scan is of a public-domain map, which overrides the holder’s licence, so choose one only if that is so.

    • Labels: each place has its preferred name; choose another it is attested by, or a rule for the whole map (the name in Latin where one is attested). Drag a label to move it, untick a place to leave it out, mark a label as a region (spaced capitals) or water (italic), and add a short note under it if you need one.

    • The map: a title, a north arrow, a small locator map, the projection (Web Mercator, or equirectangular to use the map as a Wikipedia location map), its width.

    • Licence: your own drawing and labels are CC BY 4.0 unless you choose otherwise; what the map is made of may make it CC BY-SA, and the panel says why. The sources of your places are credited in the file (for example “Pleiades (CC BY 3.0), through the World Historical Gazetteer”). If anything in it cannot go to Commons (a basemap you pasted, a source for non-commercial use only), the panel says what. You can still download the map for your own use: the file says why it is not under an open licence, and there is no description or upload link for Commons. Leave that part out, and the map can go to Commons.

  6. Download. Download the SVG (Commons prefers it, and Inkscape edits it) and the PNG. In a workflow, the first download ends it, and the other, downloaded after, is kept with the same step.

  7. Upload to Wikimedia Commons. Open Wikimedia Commons: the file’s description. Upload to Wikimedia Commons opens Commons’ upload form with the file’s name, its description (the {{Map}} template, filled in) and its licence: choose the file you downloaded there. Following the link sends that name and description to Wikimedia Commons, in the link; nothing else is sent. If the link is not offered, copy the description and paste it into the form.

What it cannot do: at most 200 places a map; no arrows or battle plans; labels in one language a file (make another file for another language); a map with a part whose licence is unknown, or for non-commercial use only, cannot go to Commons. The map’s settings are kept in its SVG: Remake from a map made here opens them again.

Publish a dataset¶

For a dataset already in a PLATO format: Elenchos: Check the dataset, then Agora’s four parts in order, Give every place and source a permanent address, Write the FAIR report, Build the web site and Write the permanent-address rules (see publishing your dataset). Under 3 it asks only for the base address, which is optional: minting uses it where the dataset has none of its own (see the base address).

The base address¶

A workflow that gives places addresses of their own (Map your data when the table gives regions, Trace a historical map always, Make an open map from a list or a table, and every workflow when you will publish) asks under 3 for the base address they are given under. It is the same question, in the same field, in every workflow, and optional except where regions, places traced from a map, or the places of a list or a table to be mapped, need it. The field shows the base address already in Options (Web address for your identifiers), and what you type there is written to Options too: there is one base address, used by every tool on the page.

Saving and resuming¶

A workflow is kept in this browser at every step: which workflow it is, your answers, the state of each step, its Scope, and references to the files (each file’s name, size and SHA-256). Reload the page, or come back later, and it is taken up where it was left, with the file the step works on chosen again in Choose your data for you, from what is kept (below). A workflow chosen before any file is kept too.

Where that file is not kept, the step asks for it to be chosen again in Choose your data (in Chromium, a button Open the file’s name again opens it in one click). The file is checked to be the one the workflow recorded: a different file is refused, with what differs, and is not counted. A page closed while a step was running leaves that step failed, to run again.

If the workflow’s recipe has changed since it was saved, the tracker says so. A change of words only carries on. Otherwise it stays at its last finished step, and you can Start the remaining steps under the new recipe, or leave it.

The recipes of Map your data, Match two datasets and Trace a historical map changed when the Wikidata step was added to them (they are now versions 3, 2 and 2). A workflow saved under the earlier recipe answers that step’s question as no, and takes up its remaining steps under the new recipe, the steps done kept; one already past Record the decisions restarts from that step, since the Wikidata step comes before it.

Carrying a workflow elsewhere: the project file¶

A workflow can be saved whole as one file, a project (ending .platoproj), to carry on in another browser or on another computer, or to give to a colleague. Under Save, open or share the project in the tracker, Save the project writes the workflow with your answers and its Scope, the files its steps made, the review open with its decisions, and your own starting file unless you untick Put my own file in it. A file this browser no longer keeps is left out, and the page names it. Whoever opens the project then chooses it again where a step needs it. A project never holds your WHG token, a share link, or any other key, the permissions you gave, or your other workflows. If any part of it, your own file included, contains the token or a key this page knows, the project is not saved. The reviewer’s name is in it only where a review records who decided. Keep it as you would your data.

Open a project, in the tracker, or open a project saved before at the top of the page, reads one back. Every part is checked against its size and SHA-256 before the workflow is taken up at its step, with the review reopened. Opening a project runs no step and sends nothing anywhere. If a workflow is already open, the page asks before letting it go. A project whose files will not fit in the room the browser allows is refused before anything is written. A project saved by a newer PLATO tools opens with a note that what the newer version added is not read.

From the command line, npx github:pelagios/plato-tools project info my-workflow.platoproj lists what a project holds and checks every part, without opening it.

Keeping the project in WHG¶

A workflow’s project can be kept in the World Historical Gazetteer’s Workbench instead of in a file, to open in another browser or to share for reading. The part In the World Historical Gazetteer, under Save, open or share the project, has Save to WHG, Open from WHG and Share a read-only link.

What you need first. A WHG account with its token, as for the lookups (see the WHG token), which can also be given in the part’s own field. The account must be enrolled in the Workbench, which is in beta. It cannot be joined from here: ask WHG to enrol you, through Get in touch on WHG’s development page. And the permission World Historical Gazetteer Workbench, under Projects kept in WHG in the Permissions panel. It is asked for only when you save, open, delete or share a project there, or open a share link. WHG takes projects only from the tools at pelagios.org.

What is sent. Save to WHG sends the project, the same one Save the project writes (your own file is included unless you untick Put my own file in it), with your token, which says who saved it. WHG keeps it in your own workbench without reading it. Its own pages do not show it, so Open from WHG is the only place to see it. Nothing is saved until you press the button, and not while a step is running. The project never holds your token. Which WHG project a workflow is saved to is kept only in this browser, beside the workflow. The part says when the workflow was last saved there, and whether it has changed since.

The size. WHG takes a save of at most 2.1 MB, room for a project of about 1.6 MB. Anything larger goes without some of its files: your own first, then the largest of those the steps made, never the workflow or the review. The part names those files before you save. Whoever opens the project chooses them again where a step needs them. If the workflow and the review alone are too large, nothing is saved: save the project to a file instead.

A newer save in WHG. A workflow is saved again to the WHG project it was saved to or opened from. If WHG holds a newer save than the one this browser last saved or opened, perhaps your own from another browser, nothing is saved over it, either here or in WHG. You can then Open the copy on WHG in place of this one, or Save mine as a new WHG project. A workflow not yet linked to a project is looked for first among your projects in WHG, and if one holds it you are asked to Save to it or Save as a new WHG project.

Open from WHG, or one kept in WHG at the top of the page, lists your PLATO tools projects in WHG, newest first, with your role in each, when it was saved and its version. Open reads one back exactly as a project file is read, every part checked, and asks first if another workflow is open. A project you own also has Delete. It asks first (Delete it or Keep it), cannot be undone, and stops any share link working. A workflow already open in a browser stays there.

Share a read-only link gives an address of this page ending #whg-shared= and a token, once the workflow has been saved to WHG. Anyone with the link can read the workflow as it is kept in WHG: the names in it, your decisions, the reviewer’s name and any files it holds. It always shows your newest save to WHG, not the workflow as it is in your browser. Stop sharing withdraws it, so that the link opens nothing. Sharing again makes a new link. Only the project’s owner or an editor can share it.

Opening a share link needs no WHG account and sends nothing of yours, not even a token. The page takes the link out of the address at once. If the permission is not yet given it says what the link is and asks for it, and a reload may be needed after that. The workflow is shown in the tracker as it was last saved to WHG, read-only: nothing in it can be changed or run. Make my own copy opens it as a new workflow of your own, not linked to the one shared. Download .platoproj saves it as a project file, and Close leaves it. If WHG cannot be reached, Try again. A reload then needs the link pasted again.

From the command line, npx github:pelagios/plato-tools project info 'https://pelagios.org/plato-tools/#whg-shared=…' reads the project a share link opens, with no token, and checks it as it checks a file. It reminds you that the link is now in the shell’s history.

What is kept in the browser, and clearing it¶

  • The workflow’s record, with its Scope, in the browser’s IndexedDB; and, for a workflow saved to WHG or opened from it, which project it is there (its id and version, never a token).

  • A copy of the file you began it with, and the files the steps made (the matching of the columns, the dataset, the review’s work file), in the browser’s private file storage (OPFS), so that after a reload the next step takes them without their being chosen again; and, where the browser allows, a link to the file you began with. The tracker says what is kept and its size, beside Clear them. Once cleared, a step that takes one asks for it to be chosen. Clear them lets go of the kept file too.

None of it leaves your computer, but like everything PLATO tools keeps in this browser it can be read by other pelagios.org pages on this computer (see who sees what). To keep nothing between visits, turn off Keep my working data between visits under Your working data in the Permissions panel: the workflow and its files then last only as long as the tab, and what was kept is cleared at once. Leave the workflow lets go of everything kept for that workflow. A browser that refuses storage (a private window, say) keeps the workflow for the tab only.

A workflow that is not there¶

When your answers lead to no workflow, Tell us what you wanted to do opens a new issue on PLATO tools’ GitHub, in a new tab, labelled Methodos and titled with your two answers. Nothing else is put in it: say there what you were trying to do.
